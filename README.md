# To-Do List

Учебный проект на Go, реализующий REST API для управления списком задач. Взаимодействие с приложением происходит через HTTP-запросы: можно создавать и просматривать задачи, менять статус выполнения и удалять их. Для отправки запросов можно использовать Postman, curl или другой HTTP-клиент.

Задачи хранятся в памяти приложения и теряются после перезапуска. Каждая задача определяется уникальным названием.

## Возможности

- Создание задачи с названием и описанием.
- Получение задачи по названию.
- Просмотр всех задач или только невыполненных.
- Отметка задачи как выполненной и возврат в невыполненные.
- Удаление задачи.
- Проверка входных данных и обработка ошибок с HTTP-кодами ответа.

## Требования

- Go 1.26.5 или новее, согласно `go.mod`.
- Git для клонирования репозитория.
- HTTP-клиент для отправки запросов, например curl или Postman.

## Запуск

```bash
git clone https://github.com/arccthecoder/todo-list.git
cd todo-list
go mod download
go run .
```

Сервер слушает порт `9091`. При локальном запуске API доступен по адресу `http://localhost:9091`.

Для остановки нажмите `Ctrl+C`.

## Использование через Postman

Для работы с REST API можно использовать **Postman** — HTTP-клиент, в котором удобно отправлять запросы и проверять ответы сервера.

1. Запустите приложение командой `go run .`.
2. Создайте HTTP-запрос в Postman.
3. Выберите метод и укажите полный URL, например `POST http://localhost:9091/tasks`.
4. Для создания задачи отправьте JSON в теле запроса и укажите заголовок `Content-Type: application/json`:

```json
{
  "Title": "Learn Go",
  "Description": "Build a task API"
}
```

5. Отправьте запрос. При успешном создании сервер вернёт `201 Created` и объект задачи.
6. Чтобы посмотреть список задач, отправьте `GET http://localhost:9091/tasks` без тела запроса.

Для изменения статуса отправьте `PATCH http://localhost:9091/tasks/Learn%20Go` с JSON-телом `{"Complete": true}` и заголовком `Content-Type: application/json`. Чтобы удалить задачу, отправьте `DELETE` на тот же URL без тела запроса.

## REST API

Задачи представлены ресурсами по пути `/tasks`. Действие над ресурсом определяется HTTP-методом: `POST` создаёт задачу, `GET` получает данные, `PATCH` меняет статус выполнения, а `DELETE` удаляет задачу. Данные задач передаются в формате JSON.

| Метод | Путь | Действие | Успешный ответ |
| --- | --- | --- | --- |
| POST | `/tasks` | Создать задачу | `201 Created`, объект задачи |
| GET | `/tasks` | Получить все задачи | `200 OK`, объект с задачами по названиям |
| GET | `/tasks?completed=false` | Получить невыполненные задачи | `200 OK`, объект с задачами по названиям |
| GET | `/tasks/{title}` | Получить задачу по названию | `200 OK`, объект задачи |
| PATCH | `/tasks/{title}` | Изменить статус выполнения | `200 OK`, обновлённый объект задачи |
| DELETE | `/tasks/{title}` | Удалить задачу | `204 No Content`, без тела ответа |

Вместо `{title}` укажите название задачи. Пробелы и другие специальные символы в URL нужно кодировать.

Фильтрация реализована только для `completed=false`. Запрос с `completed=true` возвращает все задачи.

### Создание задачи

Поля `Title` и `Description` обязательны и не должны быть пустыми строками. Название должно быть уникальным.

Примеры ниже предназначены для Bash:

```bash
curl -i -X POST http://localhost:9091/tasks \
  -H 'Content-Type: application/json' \
  -d '{"Title":"Learn Go","Description":"Build a task API"}'
```

Пример тела ответа:

```json
{
  "Title": "Learn Go",
  "Description": "Build a task API",
  "Completed": false,
  "CreatedAt": "2026-11-05T12:00:00Z",
  "CompletedAt": null
}
```

`CreatedAt` устанавливается при создании задачи. При выполнении заполняется `CompletedAt`, а при возврате в невыполненные это поле снова становится `null`.

### Получение задач

Все задачи:

```bash
curl http://localhost:9091/tasks
```

Только невыполненные:

```bash
curl 'http://localhost:9091/tasks?completed=false'
```

Одна задача по названию:

```bash
curl http://localhost:9091/tasks/Learn%20Go
```

Список возвращается как JSON-объект, в котором ключи — названия задач:

```json
{
  "Learn Go": {
    "Title": "Learn Go",
    "Description": "Build a task API",
    "Completed": false,
    "CreatedAt": "2026-11-05T12:00:00Z",
    "CompletedAt": null
  }
}
```

Если задач нет, ответ содержит `{}`.

### Изменение статуса

Отметить задачу выполненной:

```bash
curl -X PATCH http://localhost:9091/tasks/Learn%20Go \
  -H 'Content-Type: application/json' \
  -d '{"Complete":true}'
```

Вернуть задачу в невыполненные:

```bash
curl -X PATCH http://localhost:9091/tasks/Learn%20Go \
  -H 'Content-Type: application/json' \
  -d '{"Complete":false}'
```

В запросе используется поле `Complete`, а в ответе статус задачи находится в поле `Completed`. Если отправить пустой объект `{}`, значение `Complete` будет равно `false`.

### Удаление задачи

```bash
curl -i -X DELETE http://localhost:9091/tasks/Learn%20Go
```

### Ошибки

| Код | Причина |
| --- | --- |
| `400 Bad Request` | Ошибка декодирования JSON или пустое название/описание при создании |
| `404 Not Found` | Задача с указанным названием не найдена |
| `409 Conflict` | Задача с таким названием уже существует |
| `500 Internal Server Error` | Непредвиденная ошибка операции с задачей |

Ошибки обработчиков задач содержат сообщение и время:

```json
{
  "Message": "task not found",
  "Time": "2026-11-05T12:00:00Z"
}
```

Тела ответов сериализуются в JSON, однако текущая реализация не устанавливает заголовок `Content-Type: application/json`. Для ошибок, отправляемых через `http.Error`, используется `text/plain; charset=utf-8`.

## Структура проекта

```text
.
├── main.go           # создание списка задач и запуск сервера
├── go.mod            # версия Go и зависимости
├── go.sum            # контрольные суммы зависимостей
├── http/
│   ├── dto.go        # структуры запросов и ошибок, валидация
│   ├── handlers.go   # обработчики HTTP-запросов
│   └── server.go     # маршруты и запуск HTTP-сервера
└── todo/
    ├── errors.go     # ошибки операций с задачами
    ├── list.go       # хранение задач и операции со списком
    └── task.go       # модель задачи и изменение статуса
```

Для маршрутизации используется `github.com/gorilla/mux`. Доступ к хранилищу задач защищён `sync.RWMutex`.
